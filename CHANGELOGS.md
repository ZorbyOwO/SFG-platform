# SFG Project Changelog

This file is the required change record and handoff reference for SFG developers and coding AI agents.

## Rules for every developer and coding agent

- Read this file before changing the project.
- Record every code, configuration, database, dependency, asset, documentation, feature, modification, removal, migration, fix, or rollback.
- Use Malaysia Time (`MYT`, UTC+08:00) in `YYYY-MM-DD HH:mm:ss MYT` format.
- Keep the newest entry first.
- Use one status: `PLANNED`, `IN PROGRESS`, `COMPLETED`, `BLOCKED`, or `REVERTED`.
- Update an existing entry when its status changes instead of creating contradictory entries.
- State the affected scope, direct summary, affected files, and validation result.
- Never include passwords, keys, tokens, raw biometric images, or private user data.

## Entry format

```text
### YYYY-MM-DD HH:mm:ss MYT — STATUS
- Type: Feature | Update | Fix | Removal | Refactor | Database | Dependency | Documentation | Security
- Scope: Affected system or component
- Summary: Brief and direct description
- Files: Changed files or folders
- Validation: Tests or checks performed, or `Not run` with the reason
```
